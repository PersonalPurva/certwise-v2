Key point: fake certificates are mostly an employer and university problem (forged degrees, fake universities). For students the bigger problem is value - a ₹9 workshop certificate is completely genuine but worth very little. So we check both.

3. Result

  • Genuine + market value, for any issuer, for Indian students, in one place: not found. The closest is Credly (verified badge + job data), but only for its own badges, with mostly U.S. data and no score.
  • Genuineness on its own is crowded (142 SIH teams, government systems, paid verification companies) - so our edge is the combination, any issuer (no partnership needed) and proof for every fact.

Limits: "not found" means our searches of the web, SIH lists, Devpost / Devfolio, GitHub and the Play Store didn't turn it up.

What we built

Input

  • Certificate name (typos are fine - edit distance, Levenshtein, dynamic programming).
  • Verification link or certificate ID - or the certificate file: PNG, JPG, WEBP or PDF, up to 5 MB. Images are scanned for a QR code (jsQR); PDFs for a QR code on the first 3 pages and for clickable or printed links (pdf.js). Other file types and bigger files are refused with a clear message. Everything runs in the browser - the file is never uploaded.
  • Or scan the QR code with the camera (best on a phone): the back camera opens, a frame is checked four times a second, and the camera switches off as soon as a code is found.
  • Optional: the college / institute that issued it.
  • Not in our list? Three quick questions - who issued it, how it was earned, does it have a verification link or ID - and the same score is worked out from the answers, clearly marked as based on the user's answers.
  • Download report: every result can be saved as a one-page PDF with clickable proof links.

Answer 1 - Is it genuine?

  • Official verification link - the link is on the issuer's own verification site (domain + path checked).
  • Look-alike website - the link copies the issuer's name or is a small typo of it (coursera-verify.com, credlly.com).
  • ID looks right / doesn't match the format - e.g. Red Hat 123-456-789, then the official page to confirm.
  • Can't be verified - certificate types with no official record.
  • Fake university - issuer matched against UGC's list of 32 (typos allowed).
  • We never say "100% genuine" - the last step is always the issuer's own page, linked with one button.

Testing

  • 114 automated tests (npm test): the 13 new certificates and 3 new verification methods, the 3-question check for unlisted certificates, plus search and typos, every genuineness result (official link, wrong page, look-alike, typo domain, wrong issuer, ID formats, no record, fake university with typos, real university not flagged), the upload rules (allowed types, 5 MB limit, empty file), choosing the right link inside a PDF, market value scores, higher-value picks, the fact checker and the free-refresh helpers.
  • Browser checks of all five examples at laptop and phone widths, with no console errors.
  • Upload checks with sample files in tests/: a PNG with a QR code, a PDF with a QR code and a PDF with only a printed link all gave "Official verification link"; a 6 MB file, a .docx file and a damaged PDF were each refused with the right message.
  • 149 tests now, including the live check with a pretend issuer (so tests never touch the real websites) and the text reader.
  • Live check against the real issuers: made-up IDs on Credly, Coursera and edX gave "No record at the issuer"; a public Credly badge gave "Confirmed by the issuer" with its name, issuer and date; the same badge checked against a different certificate gave "Real, but a different certificate".
  • Text reader: a sample certificate image with no QR code was read in a few seconds; the name and link were filled in and the check ran.
  • Fixed: Credly sent a web page instead of the badge record until we asked for the record only; an unreadable answer now never counts as "confirmed".
  • Version 2 checks in the browser: the 3-question check, a PDF report for four kinds of result (read back to confirm its text and clickable links), and the camera scanner with a simulated camera showing a sample QR code. The camera still needs a try on a real phone.
  • Fixed in version 2: typing "AI-900" found "AZ-900" (a one-letter typo counted the same as an exact match) - exact matches now rank higher; long proof links were cut off in the PDF report - they now show the name and website.
  • Fixed while testing: "Commercial University Ltd." wasn't matched because of the full stop; a fake certificate showed a high market value - it now shows 0% if fake; PDF pages didn't finish drawing when the browser tab was in the background - the page is now drawn in one go, with a 6-second limit.
  • The deck passed file validation and every slide was checked as an image.

Tech used

HTML, CSS, JavaScript (no framework, no backend) · jsQR for reading QR codes, pdf.js for reading PDFs, Tesseract.js for reading printed text and jsPDF for writing the report, all in the browser · a small Node.js API for the live check (Open Badges records from Credly) · the camera through getUserMedia · Node.js for tests and the refresh script · Gemini (free) or Claude API for the monthly refresh · GitHub Actions · GitHub Pages (₹0 server cost).
